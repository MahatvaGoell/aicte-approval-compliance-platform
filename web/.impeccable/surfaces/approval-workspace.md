# Approval workspace direction

Mode: Operate.

User-pinned direction: bright off-white beige and almost-black counterparts with a very faint dark-brown undertone only, with natural red confined to compact borderless warning/error sections. No green, blue, olive or metallic accents. Keep the simplest possible user experience.

First viewport: the shared role/scoped shell and synthetic notice, page identity, then the main task. A case opens with its next action, responsible person, deadline and actual blockers. A short route stepper precedes current work. Documents, obligations, deadline calculations, assignment and history have named disclosures. All existing controls and provenance remain available.

Other screens: workspace/account selection on login; search and status before advanced application filters; a quiet Work composition with an explicit start/browse action; four form sections and an entered-fields overview; real document records as folder links; queue and calendar before the expert directory; dashboard figures retain their exact filtered report destinations.

Motion: short feedback and reveal transitions, no blocking choreography, no decorative background motion. Reduced motion must disable transitions. Keep locally bundled Inter and JetBrains Mono; no new assets, dependencies, remote fonts or scripts.

Write boundary: web frontend and documentation only. Existing user changes to package-lock.json and docs/CODEX_UI_REDESIGN_PROMPT.md are not part of this work. No push or PR.
