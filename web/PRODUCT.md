# AICTE Approval & Compliance Platform

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

Institution representatives prepare applications and provide evidence. Regional officers and committees review scoped cases; appointed experts handle visits. Bureau staff monitor work. Only the competent authority records a regulatory decision. Policy, system administration and audit have distinct permissions.

## Product Purpose

Route applications through versioned stages, identify the next responsible person and deadline, and retain a traceable evidence and event record. This is a synthetic SIH prototype, not an official AICTE system.

## Capabilities and Constraints

Existing React, TypeScript, Vite and TanStack Query frontend. Preserve routes, API contracts, query keys, all existing actions and role gates. No backend, migration or business-rule changes. Approval outcome, compliance status and lifecycle stay separate. Upload is distinct from verification and closure. Provenance and the demo notice stay visible in their existing contexts. All assets and fonts work offline. Status includes text. Both themes, keyboard access and 390–1440px layouts are required.

## Brand Commitments

The user replaced the initial cool palette with an old-money palette: warm ivory, forest green and restrained brass. The strongest requirement is simplicity: a clear main task, visible labels and named groups for secondary actions, without displaying every option at once. The supplied references guide composition, subject to these newer instructions and product constraints.

## Evidence on Hand

The live synthetic demo, repository specification and existing page map. Original captures are in ../docs/ui-before; final captures are in ../docs/ui-after. No invented metrics or official connectivity claims.

## Product Principles

- Decisions stay with authorised humans.
- Show the next task before the supporting record.
- Preserve every action while reducing simultaneous choices.
- Present actual data and honest unavailable states.
